# 面向 AI 兴趣人群的视频制作标准

原始设计日期：2026-10-04。以下保留创作目标与当时的实现边界。

2026-10-09 更新：正式流程已支持真实视频片段、组件知识库驱动的分镜设计及项目流程内的样片制作；当前默认只保留文案人工审核。阶段审核与返工以[人工审核说明](videoagents-human-review.md)为准，执行约束以[生产策略](videoagents-production-policy.md)为准。文案结尾接着证据和解释回答开头的问题，不单列“观点”段。

用户参考：抖音「基地」，账号 `jidifeng`，作品《美光发全球首款512GB内存，三星2021年就做出来了，详解》。[抖音原作品](https://www.douyin.com/video/7686446144645287209)，[作者的同题 YouTube 版本](https://www.youtube.com/watch?v=NjLIFD28W48)。本轮参考依据是作者章节及覆盖全片的 18 处实际关键帧，没有完整音轨试听；只借鉴表达方法，不将视频中的技术结论直接当作核验事实。

## 1. 成片目标

面向对 AI 感兴趣、愿意了解前沿进展并尝试工具的人，制作 3～5 分钟的 AI 资讯、
产品解释和 AI 工具使用视频。观众不需要会编程，也不默认了解模型、算力、参数或
Agent 等术语；专业概念首次出现时先讲清它能做什么、影响什么判断，再补充必要
名称。成片同时包含真实素材、引人入胜的口播和帮助理解的动画图解。

每期围绕一个清楚的主问题展开：提出疑问 → 具体案例与原始证据 → 解释关键原因 → 对照或反例 → 回答实际意义和边界。

普通人视角包括熟悉的处境、好奇、困惑和反常识。不能为了强调相关性，凭空推断某项技术会影响所有人的工作、收入或生活。

### 三种画面各有用途

| 画面 | 任务 | 素材节点需要准备什么 |
| --- | --- | --- |
| 真实素材 | 建立真实感、展示案例或提供证据 | 原图、真实截图、演示片段、原始声明与可追溯出处 |
| 解释动画 | 展示流程、关系、对照或因果 | 经核验的输入、结构、数值、单位、比较条件和推导前提 |
| 问题与解释卡 | 明确当前问题、承接转折、呈现条件和答案 | 编剧的主问题与有依据的段落解释，由导演组织画面 |

真实素材应当出现在它所支持的旁白处；不能用相关人物照片或产品标识替代功能演示、事件证据。动画和类比需要明确表达范围，不能冒充实拍或测试结果。

## 2. 人工参与是制作流程的核心

本项目采用多 Agent 的目的，是让用户能够提供信息、调整创作和审查产出。用户决定主问题、讲述角度与成片取舍，各节点分工完成研究、写作、配音建议、分镜和检查。

人工参与可以发生在制作前和阶段交付后；不必等机器审查失败才介入。工作台应把每阶段的产出、依据、缺口和可执行操作放在一起，便于用户判断下一步。

### 四种人工操作

| 操作 | 用户做什么 | 工作流应做什么 |
| --- | --- | --- |
| 补充信息 | 提供链接、素材文件、背景、问题或制作要求 | 保存为业务输入；材料和事实重新检查后交给相关节点 |
| 直接修改 | 编辑文案、字幕或分镜 | 保存新版本，检查修改后的产物，重新计算受影响的下游内容 |
| 提交修改意见 | 指定段落或镜头，说明如何调整 | 将意见连同对应版本的产物交给目标节点，生成修订稿和处理说明，再审查 |
| 审核与继续 | 确认当前产物，或指出问题并退回 | 确认后进入下一阶段；退回时明确修改目标与后续检查 |

“提交修改意见”和“直接修改”是不同动作。用户已经改好的文案应作为当前稿件使用；用户要求 Agent 改稿时，才根据意见生成修订稿。不能把返工说明仅保存成审核记录，就宣称已完成协作改稿。

### 每个阶段如何参与

| 阶段 | 人工可以介入的内容 | 节点交付后供用户判断的内容 |
| --- | --- | --- |
| 素材 | 确定主问题，提供出处与截图，补齐缺口，调整研究范围 | 事实依据、可用画面、解释所需材料和具体缺口 |
| 文案 | 选择切入角度，改开头、段落与结尾，要求编剧重写 | 当前稿件、机器审查意见、修改说明和来源 |
| 配音 | 试听，调整情感、语速、停顿与读音 | 实际音频、时间对齐和待修正的位置 |
| 导演 | 替换素材，调整图解、镜头顺序与表现方式 | 分镜预览、音画对应关系和画面解释目的 |
| 剪辑与审核 | 查看成片，指定时间点提出问题，确认修订结果 | 实际视频、问题定位、检查结果和当前版本 |

用户可以修改代码自行编排额外审核点。当前默认文案、分镜和成片三个阶段必须等待人工确认；其余阶段按既有缺口待办处理。没有设置审核点的阶段也应允许用户在下一阶段边界提出调整请求；执行中的版本不能直接覆盖，暂停请求的生效位置需要在工作台明确展示。

### 意见、版本和重跑范围

人工要求属于业务上下文。`VideoState` 应交接当前制作要求、当前版本的产物、仍有效的修改意见和审核决定；这些内容不随工具调用记录一起清除。各角色的固定提示词独立保存在 `videoagents/prompts/*.md`，节点只负责加载并选择业务输入。历史意见需要注明对应阶段、产物版本和是否已处理，避免旧意见误用到新稿件。

目标重跑策略如下，尚不代表当前代码已经实现这种精度：

- 文案的口播原文变化：重新生成配音、时间对齐、分镜、视频与审核。
- 只调整配音表现：保留文案，重做配音及依赖实际音频的下游内容。
- 只改画面且不改变口播：保留文案与有效音频，重新检查分镜、渲染与审核。
- 补充证据或改变主问题：先重新检查材料，再判断文案及画面是否需要修改；旧审核决定按其依赖失效。

例如用户提出“开头太技术化，先让普通人看懂它能做什么”，应把当前稿件和这条意见交给编剧，产出修订稿及说明，再交给文案审查；文案确认后才重新配音和制作画面。用户补充操作演示，则先登记真实文件及出处，再检查它是否能支持所要解释的功能。

人工确认不能跳过来源、文件、音频对齐和渲染等硬检查。用户补充的事实也要保留出处和核验状态；用户的讲述偏好与事实证据分别使用。

### 当前基础与待补齐的协作能力

2026-10-04 时，`HumanReviewNode` 支持阶段暂停、确认、返工、取消及记录；默认注册的 `human_review` 尚未接入主流程。2026-10-05 已通过三个明确的阶段人审接入，具体路由见人工审核说明。前端已有素材上传、制作要求编辑、文案编辑、分镜编辑和阶段审核界面，保存修改会创建新版本。

当前 `revise` 的行为是记录说明、结束本次执行并回到草稿；模型调用尚未把这条人工意见作为改稿输入。仍需补齐：阶段内自然语言修改意见、目标节点处理与回应、按依赖重跑，以及主动请求在阶段边界停下来的操作。这些能力是待实现规格，本轮不自动改图或修改运行代码。

人工审核的已有编排方式见 [在工作流中插入人工审核](videoagents-human-review.md)。

## 3. 素材节点的交付

保留“用户提供 + 搜索补充”，由本地 Codex CLI 或 Claude Code CLI 自主选择可用检索技能。`collect()` 继续直接启动模型，不恢复已删除的外部检索计划和逐平台调度代码。

每期先明确主问题和所需材料，再搜集能支持讲解的内容。搜到链接、读取正文、取得图片、取得可播放视频是不同的完成状态，必须按实际结果记录。

最终素材包需要说明：

- 主问题及围绕它的两三个关键解释问题。
- 每项事实的原始出处、正文或字幕摘录、日期和适用范围。
- 每项视觉素材的真实文件、关联来源、用途，以及适合说明哪个问题。
- 图解所需的关系、流程、数值、单位、比较条件和不确定性。
- 明确的缺口：缺哪项证据或画面、用户可以补什么、是否存在合适替代材料。

上述交付是待补充的业务契约，当前 `MaterialResearch` 只有 `sources`、`visuals`、`limitations`，不能把这些新增要求当成已有结构字段。

素材节点不承担最终文案和精确分镜。它交付编剧可以引用、导演可以使用的研究结果和真实文件。

### 素材机器审查与人工补充

建议编排：素材采集 → 素材机器审查 → 通过后进入编剧；关键材料缺失时暂停，人工补充后再次审查。实际节点与边由用户决定，不在本文中自动更改现有编排。

机器审查检查主问题是否有证据、核心解释是否完整、关键画面是否真实可用、素材是否匹配其用途。不以平台数量、链接数量或装了多少技能代替完成验收。

人工待办需要指出具体缺口，例如“缺少原始操作演示”“缺少变化前的对照”“只有官方宣传，缺少支持该结论的测试条件”。新增材料或修改主问题后重新审查，旧版本的通过结果不能直接沿用。

## 4. 编剧与文案审查

编剧以素材包为依据，把一个主问题写成可以听懂的推理过程：

- 开头让观众知道哪里值得追问，并在后文回答；悬念不能依赖夸大、虚构或隐瞒必要条件。
- 每段推进问题、证据、原因、转折或结论，避免平铺产品参数与新闻摘要。
- 术语按需解释，优先使用具体案例和恰当类比；类比不替代证据。
- 旁白关联事实来源和可用素材，区分已证实事实、作者判断与尚未确认的信息。
- 收尾回答主问题、适用对象和边界，不机械加入行动建议。

文案审查同时检查事实依据、因果链、开头吸引力、口播清晰度和画面可解释性，逐条指出需要改写的段落。沿用现有编剧与审查节点的讨论循环。

固定提示词从各角色独立 Markdown 加载。节点只向 `VideoState` 交接最后业务产出，工具调用历史不进入下游上下文。

## 5. 导演与 Remotion

导演根据实际配音时间安排素材和图解，每个镜头明确“观众此时需要看懂什么”。一句旁白可以对应多个画面节拍；需要持续解释的图解也可以跨多句旁白展开。

需要补充的画面能力包括：

- 图片与真实截图的局部放大、重点标记、来源展示。
- 真实视频片段的入点、出点、静音或原声选择，以及与旁白的时间对应。
- 因果链、关系图、流程分步、条件对照、数据演算和瓶颈示意。
- 统一的视觉空间、卡片层级和推拉平移，让观众能够跟随同一条解释线索。

第一版可以用 Remotion 的二维与透视分层画面验证表达效果。参考视频的真实三维场景、模型资产和连续相机运动属于进一步制作投入，不能仅靠修改提示词宣称达到相同成熟度。

## 7. 用样片验收效果

此前已制作约一分钟的 Muse demo。以下区间作为后续验收参考；当前按用户要求先优化 Prompt，不制作新样片，再由实际稿件和视听结果验证并扩展到3～5分钟。

| 大致区间 | 叙事任务 | 画面任务 |
| --- | --- | --- |
| 0～8 秒 | 提出清楚且真实的疑问 | 一项真实素材加简洁问题表达 |
| 8～20 秒 | 展示案例与证据 | 第二项相关素材，放大关键位置 |
| 20～40 秒 | 解释一个关键原因 | 分步展开关系、流程或对照动画 |
| 40～50 秒 | 展示差异、代价或反例 | 回到真实素材或有条件的对照 |
| 50～60 秒 | 回答开头问题及边界 | 收束图解与结论 |

区间是制作参考，实际镜头以实测音频为准。素材数量随题目需要决定，不作为凑数指标。

验收时检查：普通观众能否复述主问题与解释；开头的疑问是否得到回答；关键判断是否有证据；素材是否匹配旁白；图解是否真正帮助理解；字幕、来源和声音是否清楚；缺口是否如实保留。渲染成功只能证明文件生成，成片质量需要观看和试听验收。
