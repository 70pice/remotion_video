# 短视频节点 Prompt 设计

2026-10-07 适配：现有 Graph 顺序保持素材 → 文案 → 一轮文案审查 → 有意见时编剧改稿 → 人工审稿 → 配音。下面早期设计记录中的成片复核不再属于当前生产图。

现在修改文案相关 Prompt 的对应关系：

| 维护内容 | 文件 | 代码调用 |
| --- | --- | --- |
| 用户重写的编剧创作风格、输入说明、Script 字段 | `videoagents/prompts/screenwriter.md` | `nodes/screenwriter.py` 的 NARRATIVE_PROMPT，初稿和改稿共用 |
| 初稿交付约束 | `videoagents/prompts/screenwriter-draft.md` | 编剧 PROMPT，只返回 Script |
| 机器意见及人工反馈改稿 | `videoagents/prompts/screenwriter-rewrite.md` | 编剧 REWRITE_PROMPT，返回 ScriptRewrite（完整 script + response） |
| 用户重写的文案审查标准 | `videoagents/prompts/script-reviewer.md` | `nodes/script_reviewer.py` 的 PROMPT，返回 ScriptCritique |

`screenwriter-rewrite.md` 是编剧改稿指令，不是审查角色文件；这次把该处用户重写的审稿内容接到实际审查节点使用的 `script-reviewer.md`，并恢复初稿/改稿的接口指令。

动态资料不是 Markdown 模板占位符：`JsonModel.invoke` 按节点 fields 选择共享 VideoState，`JsonModel.call` 将选中字段序列化为 JSON，直接拼接在实际 CLI Prompt 的「上下文」后。初稿拿 brief、research、assets；改稿还拿当前稿和讨论、适用人工反馈；审查拿当前稿、讨论及同一份研究/素材，有人工返工反馈时也一并读取。research 包含已经取得的来源正文和真实画面清单，工具过程被清理。密钥不进入角色输入。

来源硬校验同时认可素材节点已读取的冻结研究来源：正文非空、状态为 skill_read、来源产物 ID 与 SHA256 必须匹配本任务实际登记的 source 产物。只有 URL 或伪造回执不能通过，事实稿仍须有带原始出处的真实证据图片、截图或视频。报告解读的审查通过标准是回答本期主问题，不强行变成工具推荐；审查意见保持简短，完整改稿交编剧节点完成。

`Script` 新增向后兼容的 title_hook、opening_visual、final_answer，供人工审稿和导演读取；实际配音只朗读 segments[].narration。title 和唯一 segment_id 仍须填写，当前 revision 由节点绑定。Prompt 在模块导入时读取并缓存，修改后需重启空闲 Worker 才生效。

历史记录：2026-10-04 初版；2026-10-05 补充全组件生产接入；2026-10-06 默认受众曾调整为没有技术背景的普通大众，清除程序员默认示例，新增开发者界面预设边界。当时交付是固定 Prompt 与交接标准，没有调用真实模型、配音或渲染制作新样片。2026-10-07 曾转为前沿资讯与 AI 兴趣人群；2026-10-08 用户确认以“普通人与 AI”为主线，当前规则见下文。

## 创作方向

账号主线是**普通人与 AI：用真实故事，讲清 AI 怎么影响普通人的钱、工作和生活**。作者是大厂程序员，观众可以不主动关注 AI、没有技术背景，只要关心事件与自身处境的关系。新任务默认受众为“关心 AI 如何影响自己的钱、工作和生活的普通人，无需技术背景”，替代原来的“前20%”兴趣人群定位。

选题可以是 AI 诈骗与避坑、真实成功与失败案例、工作与收入、家庭与日常生活、热点说法核实，不设每期清单或固定比例。前沿资讯、工具和机制服务一个观众在乎的问题；保留真正影响结论的版本、技术差别和统计口径。成功也包括完成任务、节省时间或改善生活；自述不等于独立验证，营收不等于利润，个案不承诺普遍可复制。诈骗题核实 AI 的真实作用，不虚构恐惧、责怪受害者或写复刻教程。不强迫每期购买建议、卖课或引流，默认个人视频用途不变。

本次通过本机 Claude Code 调用豆包 `doubao-seed-2-1-pro-260915` 改写编剧、文案 Reviewer，以及素材、导演和组件学习中的定位要求；同步前后端新任务默认受众。调用原文、输出和模型回执保存在 `.omx/artifacts/ask-claude-ordinary-people-ai-*`。固定 Prompt 在模块导入时加载，空闲 Worker 重启后生效；已有任务保留其明确填写的受众，不自动改稿或跳过人工审核。`shared-style.md` 后续已删除，避免共享规则与角色 Prompt 冲突。

作者观点自然进入证据解释与结尾；事实、来源说法、推断和真实体验分别表述，不编人物、对白、心理活动、大厂内部消息或亲测。资料没有真实主角时用有来源的事件，不强行写逆袭故事。常规时长为3～5分钟；具体项目以 `brief.audience`、`brief.target_seconds` 和用户要求为准，明确指定专业受众的单期仍可制作。

每期只围绕一个主要问题，把它讲成“具体处境 → 案例或证据 → 为什么 → 差别或限制 → 得到答案”。这是一条推进原则，不能每期机械套同一组问句和转场词。借鉴「基地」的具体切入、证据穿插和画面解释方法，选题与判断仍以本期资料为依据。

旧 Prompt 对来源和 JSON 结构约束较多，对观众为何继续看、信息怎样推进要求很少。因此文案容易变成功能清单，导演容易把旁白再次写在卡片上。现在每个角色都要解决一个具体的创作问题，并交付下一个角色能使用的内容。

## 固定 Prompt 的组成与位置

每个 Prompt 包含：角色目标、可读取输入、具体判断方法、不能越过的事实或执行边界、交付验收标准、现有 JSON 契约。编剧的初稿和改稿共享同一个叙事标准（[screenwriter.md](../videoagents/prompts/screenwriter.md)），避免初稿重视叙事，改稿只会修格式。

创作标准现在以独立 Markdown 存放在 [videoagents/prompts/](../videoagents/prompts/)，每个角色一个文件，节点里只保留同名的 `PROMPT` 常量。这样调 Prompt 不需要读节点代码，也能在编辑器里直接 Review diff。不新增 agent 文件夹，也不把 Prompt 藏在模型供应商层。运行时用户要求通过当前节点实际读取的业务字段传入；没有提供的意见不能假装已经收到。

新任务的 `brief.creative_direction` 是用户给的本期方向、切入角度和重点。素材节点以此确定研究问题，编剧结合核验后的资料创作完整口播，不能把方向原文直接当成朗读稿。`brief.script_text` 只为历史任务保留旧的现成文案路径。

| 节点 | 本次模型读取的业务输入 | 最终产出 | Prompt 文件 |
| --- | --- | --- | --- |
| 素材 | brief、assets、settings 中的检索配置 | MaterialResearch；实际正文、图片和截图经校验后进入研究与资产清单 | [materials.md](../videoagents/prompts/materials.md) |
| 编剧 | brief、research、assets；讨论改稿再读取 script、script_discussion | Script；改稿为 ScriptRewrite，包括完整 script 和 response | [screenwriter.md](../videoagents/prompts/screenwriter.md)、[screenwriter-draft.md](../videoagents/prompts/screenwriter-draft.md)、[screenwriter-rewrite.md](../videoagents/prompts/screenwriter-rewrite.md) |
| 文案审查 | brief、script、script_discussion、research、assets | ScriptCritique：APPROVE 或带具体意见的 REVISE | [script-reviewer.md](../videoagents/prompts/script-reviewer.md) |
| 配音指导 | brief、script、settings 中的声音配置 | VoiceAdvice；其后实际调用语音服务并进行时间对齐 | [voice.md](../videoagents/prompts/voice.md) |
| 导演 | brief、script、实测 timeline、research、assets、asset_metadata | 完整 Timeline | [director.md](../videoagents/prompts/director.md) |

| 成片复核 | brief、script、timeline、research、assets、reviews | ContentReviewAdvice | [review.md](../videoagents/prompts/review.md) |

### 加载方式

[prompts/__init__.py](../videoagents/prompts/__init__.py) 提供三个函数，节点调用方式和之前的内联常量完全一致：

- `load_prompt(name)`：读取并缓存 `<name>.md`；文件名只允许小写字母、数字、连字符和下划线，拒绝路径穿越。
- `compose(*names)`：只按传入顺序拼接指定角色 Prompt。编剧初稿和改稿会在本角色叙事标准后拼接各自交付指令；不会额外注入共享风格文件。
- `render(name, **variables)`：替换 `{{变量}}` 占位符，缺变量或给了用不上的变量都会报错，防止 Prompt 里残留字面花括号。导演和组件学习只渲染各自模板；导演注入 9 个适配器的 `COMPONENT_PROPS_EXAMPLES` 紧凑 JSON，以及按 `brief.usage` 过滤的完整生产组件目录。

## 全链路受众契约（2026-10-08 更新）

当前执行“普通人与 AI”定位，作者的程序员身份用于帮助解释证据与机制，不要求观众从事这个行业。执行规则：

- 旧的、未被运行时引用的 `screenwriter-prompt-v2.md` 已删除，实际维护入口仍是上表列出的角色 Markdown。
- 素材、编剧、文案审查、导演和组件学习保留各自现有的账号定位；配音、剪辑等角色依据本期输入执行自己的职责，不再统一继承额外的受众与风格条款：
  - 默认观众关心钱、工作和生活，可以不主动关注 AI；不预设其会编程或从事 AI 行业，具体深度以本期 brief 为准，不要求每期从零解释所有常识。
  - 关键机制和术语解释到足以理解本期证据与判断，必要时先用动作或结果说清含义；不把型号、版本、原理或个人判断本身作为删除或退稿理由。
  - 精确数字与单位原样保留；只有难以直观理解、且影响判断的数字才给真实
    可比的生活尺度，日期、价格、次数等直观数字不强行类比；类比不冒充实测。
  - 例子服务本期主题与目标观众，可用工作、生活或相关开发场景，不把所有选题强行改成生活小窍门或工具购买题。
  - 通俗化不得牺牲事实准确性：删掉条件、夸大效果或改写结论的“好懂”，按失实处理。
- 各角色在自身 Prompt 中承担当前定位。编剧交付真实处境、AI 的实际作用与有依据的判断；文案审查检查观众是否理解事件、关系与结论，不要求每期工具推荐或实操清单。素材区分自述、宣传与独立证据，导演用相关人物、场景、行为、结果与证据画面帮助理解；裸抛术语/数字、开发者界面滥用仍分别属于 clarity、visual 问题。

### 开发者界面预设边界

152 个固定预设中含终端、代码、光标走读类画面（如 TerminalSimulator、CursorTrack、CodeMorph、CodeReveal、claude-code、glass-code-walk、terminal-typing-log）。源码受许可证与哈希约束不能改，因此规则写在 [component-study.md](../videoagents/prompts/component-study.md) 和 [director.md](../videoagents/prompts/director.md)：

1. 只有本期主题确实相关（讲的就是编程类 AI/开发者工具，或画面直接支撑口播那一步）才可选；不当通用“AI 氛围”素材或填空转场。
2. 普通观众不用读代码也能理解：重心在动作和结果（输入什么、跑起来、给出什么），关键步骤由旁白、标题或放大指认讲清。
3. 预设内置代码、终端日志与数据仍是模板内容，一律不能当本期事实证据。

[test_prompts.py](../tests/videoagents/test_prompts.py) 覆盖各节点只加载自己的角色文件、导演及组件学习不附加共享指令、共享文件已删除、新任务默认受众，以及现有输入输出契约与导演的开发者预设边界。创作质量仍需人工审稿判断；静态回归不代表已经制作或审核过一条新视频。

Markdown 位于包目录内，wheel 会原样带上 `videoagents/prompts/*.md`（已用 hatchling 实际构建并核对包内文件清单）。[tests/videoagents/test_prompts.py](../tests/videoagents/test_prompts.py) 覆盖：全部文件可加载、无孤立 Markdown、包数据可被 `importlib.resources` 读取、加载器安全校验、各节点常量不含未渲染占位符，以及契约依赖的关键措辞仍然存在。

节点继续通过同一个 `VideoState` 交接最终业务内容，沿用工具记录清理和契约校验。此轮没有改节点顺序、调用方式、模型配置或数据结构。

## 素材：为讲述准备依据和可用画面

先理解用户想解释什么，再核验用户已有材料，用检索补缺口。素材量由问题和时长决定，平台数量、链接数量、技能数量不作为成功指标。

| 选题 | 必须考虑的材料 | 不能混淆的情况 |
| --- | --- | --- |
| 新 AI 科普 | 产品身份、发布日期、具体任务案例、旧做法与新做法、关键机制、失败或反例、可用条件、费用和权限边界 | 官方演示与独立实测；做出动作与任务成功；能力介绍与人人可用 |
| 大事件讲解 | 发生日期与报道日期、关键时间线、各方原始声明、同口径数据和历史对照、具体影响、不同解释的依据 | 已发生与计划发生；先后顺序与因果；证实的影响与预测；原始声明与转述 |

每项正文保留实际读到的原文或摘录。另附清楚标注的“素材备注（研究判断，非来源原文）”，解释它支持什么、比较条件是什么、不能证明什么。不能把 Agent 的概括伪装成来源原文。当前正文交接最多保留文件前16000字符，因此优先选取相关真实摘录与上下文，让关键材料和备注处于这个范围内。

每张图的 `description` 说明适合配合哪条说法、证据焦点在哪里、用于证明还是辅助理解。截图只有网页文字时，就证明该声明存在；不能因此证明产品任务已成功执行。用户补充材料也需要同样核验。

当前只使用 `sources / visuals / limitations`：工作假设和主问题写在有标签的说明中，缺口指出“缺什么、影响哪个结论、人工可以补什么”。这些不是新增的结构化字段。独立的素材机器审查节点仍由用户后续编排，本轮未自动添加。

## 编剧与审查：把资料写成有推进的口播

2026-10-05 根据用户 Notion 记录补充开头留存、持续观看、信息密度与互动
价值的创作规则；初稿与讨论改稿共用，并贯穿导演、剪辑预检和最终复核。
来源、角色分工、题材适配及实际表现数据边界见
[短视频黄金指标与创作规则](videoagents-short-video-metrics.md)。

编剧先选择一个有资料和画面支撑的主问题。开头一两句必须具体，让观众知道值得追问的地方；后文逐步回答，结尾兑现。不是先报产品名，再逐项念功能。

例如，以 AI 助理选题讨论切入角度时，可以问：“AI替你点完按钮，算不算真的把事情办成？”这是待选择的叙事问题，不是对 Muse 能力的事实结论。采用这个角度，就需要任务案例、完成依据、失败或确认环节，材料不够时缩小讲述范围。

每段推进问题、案例、证据、原因、对照、转折或结论中的一项。旁白写成短句和自然标点，一段一个主要信息，较长解释拆成连续段落。这样既能听懂，也能给现有“一段对应一个镜头”的导演基线提供明确画面任务。通常一段1～3句、宜不超过72字，这是表达指导，不是实测时间戳。

`screen_text` 通常是8～20字的问题、关系或结论；完整旁白已经会生成字幕，不要再复制一遍。`source_refs` 与本段实际说法对应，`asset_ids` 与画面用途对应，不把全部来源或任意图片机械挂在每段上。

官方演示、独立测试和作者判断必须分清。首次自然交代资料性质，之后无需每句重复同一免责声明；会改变结论的条件仍在相关句保留。不能为了好听，把官方介绍写成实际体验或验证成功。

审查节点同时检查事实与表达。开头空泛、全稿平铺、推理跳步、术语难懂或关键画面无依据，都属于需要修改的实质问题。反馈必须定位当前段落，说明哪一句有问题，给出删、换、合并或具体改写方向；不能只说“更有吸引力”。

改稿依据最后一轮审查，提交完整 Script 与独立 response。response 解释本轮怎么改、哪些意见因证据不足暂不能采纳，不进入朗读正文。已解决的问题不反复提出，纯风格偏好不应导致无限返工；讨论轮数和人工介入仍沿用现有流程。

人工反馈标记为已应用后，最终机器改稿仍接收 `extras.human_feedback`，保留本期方向和用户约束；`applied` 只控制是否再次开启返工周期，不表示后续改稿可以忘记该方向。用户观点、本期推论与来源作者结论须分清，不能把本期预测归给报告作者。

## 导演：每个画面解决一个理解问题

导演始终问：听到这一段时，观众还需要看懂什么？选型根据内容用途，而非为了凑齐所有组件。

黄金指标同时约束视觉信息交付：在实测前 3/5 秒建立观看理由，中段随证据、
比较和解释推进，结尾清楚呈现判断与边界；减少重复大字和无关动效，保留
复杂内容的理解空间。所有优化都在已有镜头和组件字段内进行，不改实测音频。

| 画面用途 | 当前组件 | 设计要求 |
| --- | --- | --- |
| 建立问题与强调转折 | title、keyword | 一个简短焦点，不重复整段字幕 |
| 展示事实与具体对象 | evidence、image_focus、video | 真实且相关的图片或视频；有依据才标记证据位置，清楚展示出处；视频须有实测可用区间 |
| 看清差别 | comparison | 同口径的两方条件和结果，不偷换概念 |
| 看懂关键数值 | data | 清楚保留单位、日期与条件；当前是数值卡，不是任意图表 |
| 看懂过程 | steps | 当前支持1～4个步骤对象，分清操作流程与推断的机制 |
| 回答开头 | conclusion | 收束一项可复述的判断，不机械加关注话术 |
| 补充节奏、界面或转场视觉 | 152 个社区 preset | 从动态目录按表达用途选择；固定 `props={}` 且不接收素材，内置演示内容不作为事实证据 |

每镜头一个主要信息，正文作辅助，字幕承担逐句阅读。重点截图要服务当前说法，不能只是装饰；未知图像焦点或尺寸不能凭空编出精确裁切位置。

导演只能使用已导入图片或视频的 `timeline_src`、当前任务动态白名单中的组件与已经支持的 props。生产清单包含 9 个可参数化适配器和 152 个固定视觉预设；同一预设会按 timeline 方向选择横版或原生竖版实现。Talkcraft 预设不进入商业任务清单。固定预设不能接收 `asset_src` 或自定义 props，因此需要真实事实、素材或数据时优先选择参数化适配器。保留实测音频、字幕和镜头帧区间，也保留视频尺寸与帧率。不能虚构新素材、任意动画参数，或根据预计1.3倍语速重新估计镜头时长。

## 配音与剪辑：表演有收放，检查可定位

配音指导在不修改旁白的前提下，给出好奇的开头、重点重音、转折收放、清楚的解释段、自然呼吸和结尾收束。情绪饱满不等于全程喊叫，不能给每句话都安排高潮。指导只说明怎么读，不能伪造已经听过的效果。

用户已明确偏好1.3倍与更饱满情绪。实际倍速由 Settings 的语速参数控制，`voice_speech_rate=30` 对应1.3倍；Prompt 不能替代这个请求参数。本轮没有修改已保存设置。实际设置仍优先于模型建议；支持 expressive 时，简洁的自然语言表演指导才进入 `context_texts`。

剪辑节点目前是模型预检加实际 Remotion 执行。模型根据实测帧区间检查信息停留时间、标题与字幕的重复、画面主次、组件与旁白是否对应。每条意见定位 `shot_id` 和已有帧区间，说明问题及具体改法，写入当前 schema 的文本字段，不新增位置字段。

预检还会对照实际字幕与覆盖开头 3/5 秒的镜头，检查观看理由是否出现、
中段是否持续交付信息、选择依据是否可理解与转述。问题按来源交回编剧或
导演，不用快速切镜、加速声音或预期完播率替代具体判断。

缺资产、明显错误或关键内容无法理解时，可以给阻塞 finding，交给相应角色或人工修复；一般风格优化给非阻塞建议。预检阶段不能声称看过成片或听过音频。建议会保存供 Review，当前不会自动改 Timeline，也不会自动增加 BGM、转场或素材。

## 人工 Review 与后续验收

先审本轮 Prompt 的目标和取舍，再决定下一稿采用什么主问题。后续运行建议在素材、文案和分镜交付后逐项看：

1. 素材是否能支撑主问题，用户还需要补哪项证据或画面。
2. 文案只听也能理解吗，开头是否具体，每段是否推进，结尾是否回答。
3. 分镜是否展示证据、解释关系，还是只有旁白文字换了背景。
4. 实际音频的重音、停顿、转折是否有效，实际成片的画面是否来得及理解。

原始 Prompt 设计时，正式外部视觉资产仅支持图片/截图。2026-10-05 更新：现已支持真实视频片段及 `video_clip` 适配器；导演先学习全部 152 个原生竖屏组件和 9 个生产适配器，再基于实际音频编写分镜。文案、分镜、成片分别经过人工审核，意见驱动的返工路径见[人工审核说明](videoagents-human-review.md)。现有约束仍保留：不改变实测音频及既定帧区间；固定预设不接收自定义素材；剪辑建议不自动变更 Timeline，成片画面返工先回导演改镜头，再重渲染并复审。

契约测试能够证明输入、输出、来源检查、讨论路由和时间轴约束未被破坏，不能证明新文案一定吸引人或新声音已经像真人。表达质量仍需后续实际稿件、音频和视频 Review。

## 2026-10-05：自然收尾与阶段人审

文案不在最后另起“观点：”“个人感受：”或突然加入购买建议。末段延续前面的案例、比较与条件，回答开头的问题；删去重复总结和无依据的劝告。末段中的事实和判断同样关联来源，来源信息保留在元数据中，不朗读来源标签。导演结尾沿用前文的证据和解释对象，剪辑检查转接是否自然，不机械改成个人观点海报。

人工审核在文案机器审查后、分镜检查后、实际成片生成后暂停。确认后继续，返工意见随当前产物快照交给相应节点，修订产物重新通过检查和人工审核。阶段确认与最终发布确认分别记录。实际语速沿用用户最新确定的 1.1 倍，Settings 中的显式配置优先。
