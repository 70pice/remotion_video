# 三条基地参考片与 Codex Plus 成片返工

用户反馈：主问题不清楚、文案吸引力不足、长时间同一画面只换字幕、缺少有信息的重点镜头。

参考文件由用户提供，分别为 `w1__03ddf13312db.mp4`（491.939 秒）、
`w1__3226129a92d7.mp4`（877.833 秒）、`w1__0b87eb101aba.mp4`（464.701 秒）。
源文件在 `C:/Users/70pic/Downloads/`，均为 1920×1080、30 fps。仅分析讲述与视觉方法，
不把它们当作本期 Codex 的产品证据，也不复用原片镜头或逐字照搬口播。

## 核验方法

- 全时段每 0.5 秒提取底部字幕，使用本机 Windows 简体中文 OCR；这是字幕识别，
  不是已经完整听审音轨。识别原文、时间码及关键帧保存在 `.runtime/videoagents/reference-study-20261005/`。
- 结合开头逐秒画面和全片画面样本，比较画面中的对象、信息层级、图示推进与字幕。
- 旧成片 revision 4 实测 298.3 秒、28 镜，平均 10.65 秒，全部镜头超过 8 秒；
  13 镜是比较卡。导演代码及 Prompt 共同强制一段文案一镜，画面缺乏细分表达的空间。

## 实施计划

1. 先用回归证明一个旁白段可拆成多个镜头，音频、字幕、总时长与任务身份仍由程序保留；
   空洞、重叠、重复 ID、越界、过短镜头和素材不足仍拒绝。
2. 从三条参考片提取问题推进、案例解释、重点揭示和自然收尾的方法，写进共享风格、编剧、
   文案审查、素材、导演及剪辑的固定 Prompt。事实来源、真人口播和既定输出结构保留。
3. 根据观察补足可执行的视觉表达，避免只要求模型输出渲染器不支持的动画参数。
4. 经测试与构建后由正常任务 API 保存新版本，Worker 执行完整 LangGraph。
   操作者代做已授权的制作阶段审核，逐项记录证据与限制，最终发布确认留给用户。

## 完成标准

- 新文案明确回答“普通人是否需要为 Codex 买 Plus”，不滑向产品使用手册。
- 每次画面变化都交付对象、结果、差别或解释；手机上能看清关键画面。
- 所有生产产物来自正式节点，维持竖屏、1.1 倍配音及全部竖版组件学习。
- 交付真实新成片、任务版本、关键质量核验和仍待用户判断的事项。

依据是全片字幕 OCR 与实际画面抽查。字幕动画过渡区存在误识，未据 OCR 单独认定技术事实，
也未把抽帧描述成逐帧观看或全片听审。A/B 详细证据另存于各自 analysis.md。

旧片最需要改变的是重心：案例是回答付费改变什么的证据，不能变成采购教程；
权限、额度与地区是决定条件，不能占掉后半片。画面需要真实任务动作、相关结果、聚焦细节，
以及对应口播时出现的关系和答案。增加镜头数量只是手段，质量仍由实际观看判断。

## 已落地的改动与核验

- 导演可自由拆镜、跨旁白段落组织镜头及重命名 ID；程序仍保留真实音轨、字幕、总帧数和任务身份，并检查连续覆盖、素材时长及组件参数。
- `data/steps.items[].reveal_frame` 与 `comparison.right_reveal_frame` 使用镜头内的真实帧时刻；`steps.layout="flow"` 可逐项展示纵向节点和箭头。后端、渲染端与分镜编辑器使用一致的边界校验。
- 固定 Prompt 已覆盖主问题、具体付费判断、案例推进、自然收尾、真实素材区间、手机可读性、拆镜和逐项揭示。移除成片中的工程品牌与镜头计数。
- `image_focus.props.crop` 可以等比放大原截图中的已核验区域，视频沿用同样的归一化裁剪。图片无裁剪时保留原有焦点与轻推近；后端、渲染端和前端同步验证边界，不改动原素材。
- 新鲜验证：后端与 API 578 项、前端 80 项、渲染端时间轴 21 项通过；双端类型检查、前端构建、相关 ESLint/Ruff 和生产组件清单检查通过。
- 增补裁剪后，导演/Prompt/时间轴合计 131 项、渲染时间轴 22 项、前端时间轴 13 项通过，双端类型检查、ESLint/Ruff 和前端构建通过。
- 裁剪收尾后的前端全套 82 项通过；补充否定句必须进入主文字后，Prompt 的 50 项检查通过。
