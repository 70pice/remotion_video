# 来源正文编码与长度边界

`source` 工具经 `safe_get` 的公网连接、逐跳 URL 验证和 3 MiB 下载上限读取 HTML/纯文本；
解码只作用于正文提取，不改变下载文件的原始字节、原始文件 SHA-256 或来源 URL。

## 编码规则

- 先识别 UTF-8/UTF-16/UTF-32 BOM，再采用 HTTP `Content-Type` 的 `charset`。
- HTTP 未声明可用编码时，读取 HTML 前 16 KiB 中的 `<meta charset>` 或
  `<meta http-equiv="Content-Type" content="...; charset=...">`。
- 无声明或编码标签无法识别时，保持 UTF-8 默认解码与无效字节替换行为。
- `safe_get` 默认仍返回不带参数的 MIME 类型；仅来源读取显式保留 HTTP 类型参数。
- `source` MCP 最终仍保存 UTF-8 `.txt`，并计算这个实际文件的摘要。

## 正文预算

正文最多返回 256 Ki 字符（262,144），标题仍限制为 500 字符；下载仍限制为 3 MiB。
素材节点将已验证的 UTF-8 来源文件交接到共享 `research.sources` 时使用同一字符上限，
避免来源工具已返回的尾部章节在素材交接和编剧返工上下文中再次被固定截到 16,000 字符。
冻结的来源文件、摘要和 1 MiB 文件大小验证保持原样。
256 Ki 字符即使全部使用四字节 Unicode，在 UTF-8 文本中也不超过 1 MiB。
回归同时验证最坏 Unicode 与 JSON 转义正文经过 MCP 后仍低于 CLI 单事件 4 MiB 上限；
不修改累计研究事件 64 MiB 上限或其他网络、文件与来源证明约束。

该预算覆盖本次实际发现的长页，并不保证任何网页都能完整返回；超过上限的页面仍会截断。
本次不引入分页或自动选择章节，来源是否支撑具体句子仍由角色亲读及人工文案门判断。

## 2026-10-13 实测

1. [央广网原页](https://news.cnr.cn/native/gd/20260113/t20260113_527492219.shtml)：
   HTTP 200，`Content-Type: text/html` 未带编码；HTML 声明 `gb2312`，下载 20,833 字节。
   原实现按 UTF-8 解码，已保存正文中 3,905 字符有 2,903 个 `U+FFFD`；严格 UTF-8 解码
   在字节 279 失败。修复后提取 2,497 字符，中文标题正常，替换字符为零。
2. [Anthropic 官方报告页](https://www.anthropic.com/threat-intelligence-report-september-2026)：
   HTML 1,194,351 字节，提取正文 258,835 字符。`GTG-15001`、`4,700`、`25,000`、
   `2.36` 的首个字符位置分别为 227,706、228,096、228,167、229,726（从零开始）。
   原 16,000 字符返回值均未包含它们；128 Ki 字符仍不足，256 Ki 字符包含本页全部提取正文。

以上是当天网页观测，不将这些数字或正文长度视为不会变化的网页合同。
离线回归用同样的 GB2312 声明与第 22 万字符后的尾部证据复现错误，不在测试时联网。
