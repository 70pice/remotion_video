# 原生竖屏组件

本项目的短视频画布为 **1080×1920，30fps**。Studio 的 `component-horizontal` 提供横版对照；`component-vertical` 使用各组件库自己的竖屏实现。

## 竖屏适配的边界

公共部分只统一画布规格。每个组件的文字、面板、图表和动画路径要在竖屏坐标空间内排版，不能把完整的 960×540 / 1280×720 画面缩小后放进一个竖屏卡片。

- 文字动画：按手机阅读宽度换行、分层，主词可以独占一行。
- 对比和流程：左右对比可改为上下对比，流程节点与路径一起重新计算。
- 图表：重新设置绘图区、刻度、标签和图例；不能只拉长 SVG。
- 界面和文档：使用纵向内容流、较短代码行和较大的文字。
- 图片与视频：素材可以保留自身宽高比，但组件本身的布局由竖屏画布决定。
- 镜头缩放、弹入缩放等动画仍可使用 `scale()`；这与缩小完整横屏舞台是两件事。

## 来源和维护

实际竖屏实现和入口统一放在 `src/components/component-vertical/<组件库>/`，横版源码和入口放在 `src/components/component-horizontal/<组件库>/`。每个库的 `entries/<slug>.tsx` 是单组件演示入口。Talkcraft 原卡放在横版目录的 `video-talkcraft/cards/`，其 108 个文件通过导入时记录的 SHA-256 校验；竖版源码在竖版目录的 `video-talkcraft/<slug>.tsx`。

适配沿用来源组件的动画逻辑、时间参数和内容接口。竖屏的布局调整会改变视觉构图，因此不能将适配版称为原作者演示的像素复刻。原始许可和来源记录仍适用，见 `licenses/community/`。

`CommunityRoot.tsx` 将原版与竖屏版成对登记，并检查每个原版都有对应的竖屏实现。原版 ID 保持不变，竖屏 ID 为 `Vertical-` 加原 ID，例如 `Vertical-Snapcn-WordFlip`。

## 验证与换文案

`npm run typecheck` 检查所有 TSX；`npm run lint` 检查接入代码与竖屏代码。Talkcraft 原卡因字节保留而不做 lint 风格修改。

`npm run check:components` 校验原卡哈希、注册项与画布规格，再渲染起始 / 中间 / 结束帧。抽样渲染可发现加载或运行错误；文字是否清楚、布局是否遮挡还要查看抽帧和连续动画。

换文案、增加步骤或改变图表数据之后，需要再次检查换行、溢出和字幕空间。组件演示通过，不等于任意长度的内容都能自动排版。
