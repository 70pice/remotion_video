# 每个模型节点完成后的工具记录清理

参考同级 TradingAgents-astock 的 `create_msg_delete()` 和 `Msg Clear <角色>` 图节点：工具调用期间使用消息，阶段结束后清空消息，最终报告保存在共享 state 的业务字段。

本项目 CLI 子进程只返回最终 JSON，没有 LangChain messages 通道，因此不引入 `RemoveMessage` 或占位对话。使用同样的图边界，在素材、编剧、文案审查、配音、导演、剪辑和审核七个节点后各注册一个显式清理节点，再执行原来的条件路由。

## 修复范围

- 扩展现有 `clean_handoff()`，递归清除最终上下文中的消息、工具调用/结果、搜索过程和操作流水字段；正文文字、最终意见、稿件与媒体引用保持不变。
- 明确的工具历史字段是保留字段，不能用作 `extras` 的最终业务字段。通用 `tools` / `operations` 只按运行记录/素材审计位置排除，保留同名的自定义最终软件清单和制作步骤。修复 extras 合并 reducer，避免旧工具字段因遗漏保留语义再次进入 checkpoint。
- 清理审计/原始清单产物引用及其元信息，审计文件与 UNKNOWN 提交台账留在数据库或审计目录，不进入下一模型的输入。
- 保留原路由名、暂停 token、讨论轮次、取消/版本检查和最终产物；不改变 CLI 权限，不安装或配置平台服务。
- 无兼容采集 fallback；历史 research 的失败信息继续转换为资料局限。

## 验证

清理前交接、上下文、节点测试 57 项通过。先补充能重现嵌套工具字段与 extras 合并回流的回归，再实现修复。验证七个清理节点、真实 LangGraph/SQLite checkpoint、暂停恢复、文案最大轮次、UNKNOWN 去重和既有业务数据保留；随后执行全量后端、前端类型检查和契约检查。独立审查与实现分开。

## 执行结果（2026-10-04）

先运行新增回归，8 项失败重现嵌套历史和 extras 回流；最终交接专项 22 项、全量后端 406 项及 React 66 项通过。七角色必须经过清理节点的拓扑、真实生产图素材→编剧→配音暂停、SQLite 历史 checkpoint、最终业务数据和暂停 token 保留均已验收。既有最大五轮讨论、人工恢复、UNKNOWN 去重回归继续通过。

独立审查发现通用 `tools` / `operations` 同名业务字段可能被误删；先补充失败回归，再限制为按位置清理，保留最终软件清单及制作步骤。独立复审通过，无新增可行动问题。

Ruff、Python 编译、共享契约一致性、React/Remotion 类型检查、Remotion ESLint 通过。独立 API/worker 测试取得媒体 Range 206，两次都在未启用素材模型时暂停；隔离测试等待本机命令完成后编辑，避免把 SQL 提前写入的暂停状态误认为 checkpoint 已保存。没有触发真实模型、配音、渲染或发布。

生产工作台重新加载前确认没有 RUNNING/QUEUED 任务；重新加载后 API 健康、worker 存活。私有审计文件与 SQL 调用台账保留，清理只作用于跨角色共享上下文。
