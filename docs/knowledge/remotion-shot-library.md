# Remotion 组件知识库

这是导演节点生成镜头前必须先读的仓库知识库。它把当前生产可选组件逐项列清楚：适用于什么场景、能产生什么画面效果，以及横版/竖版实现入口在哪里。

来源：用户指定的飞书 Remotion 镜头表快照、`videoagents/component-manifest.json`、`docs/component-paths.json`、`docs/component-use-guide.json`、`docs/community-components.json` 和当前源码。历史飞书原始快照仍保留在 [remotion-shot-library.feishu.json](remotion-shot-library.feishu.json)，但生产事实以本页和仓库 JSON 为准。

## 导演使用方式

导演必须先读组件知识库，再设计 shots：

1. 先判断旁白这一拍到底需要提出问题、展示证据、解释差异、说明数字、讲步骤、建立节奏还是收束结论。
2. 再从下表按“适用场景”和“画面效果”选组件，优先使用能承载真实素材的 video / evidence / image_focus；纯解释才使用 title / keyword / comparison / data / steps / conclusion 或社区预设。
3. 先判断组件的素材接入方式：当前 196 个生产组件全部为 `native_slots`。VideoAgents 参数化适配器用强类型 props 承载事实素材；35 个 CuratedScene 精选预设使用专用原生槽；其余社区预设按组件语义进入 device、gallery、pip、data、workspace、reveal、text、motion 或 material-card 展示面。需要精确证据框、复杂数据或步骤同步时，优先使用参数化适配器。
4. 社区预设已经进入生产清单，不是随意 import 的代码入口。它们可以使用统一安全素材槽位，但演示内容、演示代码、演示数字不能当成本期事实。
5. 商业任务会过滤 Talkcraft 等非商业组件；个人任务可以使用完整个人/未指定清单。最终可选 ID 仍以运行时 schema 为准。
6. 如果组件清单和实际素材不能支持某个画面，不要凭名字想象新能力，也不要新增 props、CSS、URL 或任意代码。

当前共有 **196 个生产组件**：9 个参数化适配器 + 187 个社区预设。
素材接入能力分层：196 个 `native_slots`（9 个参数化适配器 + 187 个社区预设），0 个 `overlay`。
其中 35 个 CuratedScene 社区预设支持把 `asset_src`、裁剪、视频截取、标题、正文和强调色映射进组件自身的手机框、图库、画中画、遮罩、玻璃卡、图表或背景槽位；其余社区预设使用同一批安全素材字段，按组件语义进入 device、gallery、pip、data、workspace、reveal、text、motion 或 material-card 展示面，并保留原预设动效和构图。

- VideoAgents: 9 个
- Snapcn: 21 个
- RVE: 26 个
- Remocn: 5 个
- RemotionUI: 13 个
- Bits: 4 个
- RenderComp: 10 个
- Talkcraft: 108 个

## 场景组件组合 Playbook

账号选题先按 [普通人与 AI 镜头组合规则](account-shot-playbooks.md) 判断主题、素材条件与段落任务，
再使用以下通用场景组合。主题不是组件白名单，完整清单继续保留；实际切镜须交付新信息并换成相关新素材。

先定场景，再选组件；同一 10-20 秒段落优先按一个 playbook 连续组合，避免逐镜随机换组件。
每个组合都按“开头/主体/证据/局部/结果/收束”的职责分工选 2-4 个镜头，保持同一素材主体、颜色语义和组件家族，只在旁白的信息动作变化时换组件。

| 场景 | 适合内容 | 组合节奏 | 推荐组件组合 | 避免 |
| --- | --- | --- | --- | --- |
| 开头钩子 / 问题立住 | 前 3-5 秒先让观众看见具体对象、结果或冲突 | 一镜抛问题，一镜给证据锚点 | `Talkcraft-impact-open-title` / `Snapcn-SearchTyping` / `title` -> `video` / `evidence` / `image_focus` / `Snapcn-LaptopFrame` / `Snapcn-PhoneFrame` | 不要连续两张纯标题卡；没有证据素材时用明确问题关系 |
| AI Coding / Agent 工作流 | 输入提示词、执行工具、跑测试、生成结果 | 输入意图 -> 执行过程 -> 结果或日志 | `Snapcn-PromptSend` / `Snapcn-SearchTyping` -> `Snapcn-AgentSteps` / `Snapcn-TerminalSimulator` / `steps` / `Talkcraft-terminal-typing-log` -> `Snapcn-AnswerStream` / `Snapcn-AnswerHighlight` / `evidence` / `image_focus` | 不要把终端/代码预设当通用 AI 氛围；必须看见输入、动作和结果 |
| 产品 / 工具界面演示 | 网页、App、后台、录屏、产品能力 | 设备容器承载界面 -> 局部放大关键操作 -> 结果或限制说明 | `Snapcn-LaptopFrame` / `Snapcn-PhoneFrame` / `Snapcn-ScreenRecording` / `video` -> `image_focus` / `evidence` / `Snapcn-CursorTrack` -> `comparison` / `data` / `conclusion` | 不要一镜里同时塞完整截图、长标题和大段 body |
| 来源证据 / 官方说法 | 论文、公告、网页原文、资料出处 | 先给出处身份，再聚焦被旁白引用的句子或区域 | `evidence` / `Rve-QuoteCard` / `Snapcn-LaptopFrame` -> `image_focus` / `Snapcn-AnswerHighlight` / `keyword` | 不要把来源链接或内置 demo 文案当证据 |
| 数据 / 指标判断 | 价格、速度、比例、下载量、评测分数 | 先抛核心数字，再给口径或对比 | `data` / `Rve-StatCounter` / `Rve-ProgressBars` -> `Rve-ChartAnimation` / `Rve-LineChart` / `Rve-ComparisonChart` / `RenderComp-PixelCandlestickOhlc` | 不要凭空生成百分比、趋势、排名或赢家 |
| 前后对比 / 反转解释 | 旧方案与新方案、误解与真实答案、A/B 差异 | 先建立 A，再在转折句揭示 B | `comparison` / `Rve-SplitScreen` / `Snapcn-TextRewrite` -> `Rve-ComparisonChart` / `Rve-ImageComparisonSlider` / `Snapcn-TextSwap` / `conclusion` | 不要把两个无共同口径的素材硬并列 |
| 流程 / 方法论 / 阶段推进 | 2-4 步流程、Agent 分工、项目阶段 | 用同一结构逐项揭示，每一步有动作或结论 | `steps` / `Rve-ProgressSteps` / `Snapcn-AgentSteps` -> `RemotionUI-KanbanMove` / `Rve-ProgressBars` / `Talkcraft-chapter-progress-list` | 不要超过 4 个屏幕条目；并列名词不要伪装成流程 |
| 多素材集合 / 案例墙 | 多个案例、候选方案、图片集合、作品展示 | 先用图库建立集合感，再切一张主图或结论解释 | `Snapcn-MoodboardReveal` / `Rve-GalleryGrid` / `Rve-MasonryGallery` / `Talkcraft-gallery-wall-dolly` -> `image_focus` / `evidence` / `keyword` / `conclusion` | 不要把一张图硬做成多图案例 |
