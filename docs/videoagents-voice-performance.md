# 配音的讲述风格与起伏

## 当前复刻音色的两种模型

字节声音复刻 2.0 的 `seed-tts-2.0-standard` 不支持语音指令；即使传入表演说明，也会被过滤。`seed-tts-2.0-expressive` 是表现力增强版，支持自然语言描述讲述方式。音色 ID 保持自己的 `S_...`，资源 ID 使用 `seed-icl-2.0`，账号是否有对应权限以实际调用结果为准。[官方双向 WebSocket V3 文档](https://docs.volcengine.com/docs/6561/1329505?lang=zh)

## 工作台设置

在「设置 → 你的声音」选择字节 WebSocket，填入 `seed-tts-2.0-expressive`，再选择「情感风格预设」或编辑「情感与讲述风格」。预设包含自然、演讲（情感丰富）、热情、严肃；已有自定义风格会保留。生产短视频优先用 expressive，先按原始语速生成短样，再用风格指令补足重音、停顿和情绪。例如：

> 像真正理解内容的人在给朋友讲一个值得关注的新发现，不要播音腔、朗诵腔或逐字念稿。开头带克制的好奇，问题句自然上扬；解释段放松、清楚，给长句留出呼吸；遇到转折和反常识信息时先收一下，再加重真正关键的内容；结论坚定收住。不要字字加重，不要全程兴奋，也不要一口气读完。

「语速（倍速）」默认 1，支持 0.5～2.0。它控制整体速度，不能代替情绪、重音和停顿指导。当前生产口播建议先在 0.95～1.05 倍生成 10～15 秒短样；确认自然停顿仍在以后，再按内容提高速度。风格或语速变化后需要重新生成音频，字幕及分镜要依据新音频重新对齐，已有视频不会自动改变。保存后刷新设置页，会回读已保存的倍速和风格。

前端保存时按 `(倍速 - 1) × 100` 转为接口整数，例如 1.2 / 1.3 / 1.4 对应 20 / 30 / 40。语速适用于当前 WebSocket 合成；情感风格需要 expressive，standard 不支持情感指导。切到旧 HTTP 会清空不支持的风格和语速参数，关闭配音服务则保留配置。

配音节点保留原文，先检查朗读风险。Voice Agent 除精简的全局 `delivery_notes` 外，还按文案段落输出 `segment_performances`：每项绑定原始 `segment_id`、该段的表演指令和段后目标总停顿。计划必须与文案段落顺序、数量和 ID 完全一致，末段停顿必须为 0。用户设置优先；模型只能补充讲述建议，不能覆盖用户填写的风格和语速。模型建议不等于实际试听结果。

当配置为 `seed-tts-2.0-expressive` 且逐段计划完整时，执行器逐段合成，每段正文保持原样。它使用供应商返回的真实词时间戳裁掉每次会话的多余头尾静音，再用 FFmpeg 无变速拼接；`pause_after_ms` 是前段最后一个字到后段第一个字之间的目标总间隔，裁剪保留的头尾静音会先计入，不会再重复叠加。拼接后所有词时间戳按实际输出偏移重排，并重新校验全文及段落覆盖。Voice Agent 关闭、计划为空或当前模型不支持风格时，仍走原来的整稿合成路径。

## 短视频表演标准

配音指导按真人讲述来写，不按广告播报或新闻播音来写。合格的 `delivery_notes` 至少要说明开头、重音、转折、解释段和收尾怎么读：

- 开头用好奇、反问或轻微惊讶抓住普通观众，但不要每句话都拉满。
- 关键数字、专名、矛盾点和结论词要稍微加重；解释原因时放稳一点，让观众能跟上。
- 转折词前后要有清楚的收放，比如“但问题来了”“真正关键的是”“这和普通人有什么关系”。
- 调整语速后仍然保留标点停顿和自然换气，不逐字顿读，也不把整段压成一口气。
- 情绪更饱满指的是更像人正在讲一件值得关注的事，不是全程喊叫、夸张卖力或机械亢奋。

审听时只认实际音频：听开头是否能抓人，长句是否喘得过来，专名和数字是否读准，转折是否清楚，结尾是否有收束感。模型不能伪造试听结论，也不能替代人工最后判断。

## 实际请求与恢复

双向接口将讲述风格放在 `req_params.additions` 中。这个字段是 **JSON 字符串**，内部的 `context_texts` 是数组，只有第一条有效；语速放在 `req_params.audio_params.speech_rate`。例如：

```python
req_params = {
    "model": "seed-tts-2.0-expressive",
    "speaker": "自己的复刻音色 ID",
    "audio_params": {
        "format": "mp3",
        "sample_rate": 24000,
        "enable_subtitle": True,
        "speech_rate": 0,
    },
    "additions": json.dumps({"context_texts": ["自然讲解，问题带好奇，重点加重。"]}, ensure_ascii=False),
}
```

请求指纹绑定实际表演指令与语速，音频配置指纹绑定用户设置；改变风格不能复用旧风格的音频。逐段请求还将原始 `segment_id` 写入稳定操作键，避免相同正文的两个段落错误共用一次调用。每段完成记录可独立复用：拼接失败或进程在附件入库前退出时，恢复流程会读取已完成的供应商操作并重新组装，不会再次付费。任一段正文提交后的未知结果仍按 `UNKNOWN` 暂停，换模型、风格或后续段落都不会绕过对账要求。

本项目的表演指令先支持 WebSocket 的复刻 expressive 模型。standard 和旧 HTTP 配置不能静默接受不生效的显式风格。没有给当前复刻音色强行添加未经确认的 `emotion="happy"` 枚举，也没有把双向接口不支持的 SSML `<break>` 塞进口播正文。[官方 SSML 说明](https://docs.volcengine.com/docs/DoubaoVoice/SSMLmarkuplanguage?lang=zh)

表现力增强版仍可能存在随机性。先生成短样音，实际听重音、节奏、专名发音和音色，再决定用于全稿。[声音复刻 2.0 最佳实践](https://docs.volcengine.com/docs/DoubaoVoice/SoundReplication20BestPractices?lang=zh)
