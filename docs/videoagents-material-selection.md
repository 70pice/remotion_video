# 文案与素材门的部分取舍

人在当前 `human_review_script` 待办中只确认某些画面保留、某些画面不采用时，导演通过独立 CLI 记录部分决定：

```powershell
videoagents select-materials <job_id> `
  --reject-asset <完整素材ID> --reject-asset <另一个ID> `
  --accept-asset <保留ID> `
  --note-file <UTF-8取舍意见文件> `
  --idempotency-key <本次决定唯一键>
```

也可使用 `--note "意见"`，最多 3000 字符。两种素材参数均可重复；至少指定一个ID，未指定的素材保持原状。未知ID、同组重复、同时保留和拒绝同一ID、音频、其他人工门、旧版本或旧待办、当前版本未决外部提交会被拒绝。已有分镜或已审文案绑定被拒ID时也拒绝，不能借部分取舍静默改稿。

命令通过现有持久队列和图恢复通道执行 `select_materials` 部分决定。它保存不可变 `stage_review` 回执，包含原待办、完整口播与素材快照、保留/拒绝ID、意见和结果指纹；同时从任务的当前素材中移除被拒项。原文件、素材元信息、产物登记与审核历史保留。摄影和剪辑的时间轴校验只接受当前素材，不能使用被拒项。

执行后版本不变，文案、制作要求和来源不改；素材采集前文案批准维持原有真实状态，不生成新通过回执。图只重回本次文案与素材门，生成新令牌并继续 `NEEDS_HUMAN`，不会调用编剧、素材、配音或后续角色。部分保留也不代表整包通过，普通 `resume` 和飞书 `poll` 的决定仍只有确认、返工、取消。

默认幂等键绑定本版本的取舍内容；显式键更便于追踪同一次授权。相同命令重复运行会读取原命令并复用原待办绑定，不会把旧意见提交给新门；相同显式键配不同内容会冲突。图在保存结果后、写入 checkpoint 前退出时，租约到期且旧进程消失后，正常 worker 重领命令会复验已保存结果并恢复到新待办。

飞书「素材清单」的文本字段「采纳状态」「采纳意见」来自正式回执，分别显示保留、不采用或待审。原记录ID、附件、人工字段和评论保留；已有附件不重复上传。旧审核行的描述标记部分取舍已记录、整包未通过，并保留用户原意见与结论；新的审核行仍待审。飞书同步失败不撤销本地取舍，可修复配置后正常同步。

需要补采高清画面时，单独走素材恢复入口。该命令不负责新采集，也不以部分取舍代替整包审核。
