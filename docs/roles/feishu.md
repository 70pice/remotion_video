# 飞书多维表格工作流(人工界面)

一个视频一个飞书 Base,引擎在人工门前经本机 lark-cli 幂等同步;引擎 SQLite 仍是权威数据源,
飞书是人工界面、决策面和产物展示面。

## 数据表

| 表 | 内容 | 写入时机 |
| --- | --- | --- |
| 文案 | 段落ID/口播/屏幕文字/来源/画面需求/修改意见 | 文案门前；文案与素材门前再次同步 |
| 素材清单 | 素材ID/名称/类型/用途/来源URL/许可/文件附件 | 文案与素材门前 |
| 镜头编排 | 镜头ID/起止帧/组件/理由/画面动作/素材引用/代表帧附件 | 逐镜门前 |
| 审核记录 | 标题/阶段/待办令牌/审核要求/结论(待审/通过/需修改)/意见 | 每个人工门 |

## 决定怎么回来

- 人在「审核记录」把结论改为 **通过** 或 **需修改**(需修改必须填意见)。
- 顺序为文案门 → 素材采集 → 文案与素材门 → 配音与摄影 → 逐镜门。各门绑定各自待办令牌，文案确认不能替代后续素材或逐镜确认。
- 导演会话运行 `videoagents poll <job_id>`:读到决定后走既有 resume 通道续跑;逐镜门的"通过"
  即整包确认(自动带全部镜头 ID)。
- 飞书不可用/未配置时,`videoagents resume` 是兜底入口;任务永不因表格故障丢失。
- 逐段意见填在「文案」的「修改意见」文本字段；导演读取并汇总后，通过既有 `resume --decision revise --note ...` 交编剧返工。原生评论可供人工讨论，`poll` 只读取「审核记录」的结论与意见。
- `videoagents sync-review <job_id>` 仅同步当前暂停的人工审核资料和待办，不读取审核决定、不续跑生产。

## 配置

`videoagents settings set feishu_folder_token <文件夹token>` —— 每个新视频的 Base 建在该文件夹下,
token 记录在任务的 job_inputs；所有调用显式使用 `lark-cli --as user`，用户授权失效时停止飞书同步。

文案、素材与镜头按各自 ID 增量更新引擎字段，保留记录 ID、用户自建字段、修改意见及原生评论。
不再清表重建；旧版本删除的段落和用户手工行保留在表内，审核以当前任务列出的 ID 为准。
旧 Base 缺少「修改意见」时只补建该文本字段；已有同名非文本字段时停止同步，不覆盖数据。
「审核记录」按待办令牌去重，重复同步保留人填写的结论和意见。

没有配置文件夹时，常规人工门不会创建 Base。明确请求根目录创建可用
`videoagents sync-review <job_id> --root`，需要已有人工审核待办和有效用户授权。
此命令创建的 Base 仍归当前任务；之后返工的人审门复用并同步该 Base，不要求补设文件夹。
