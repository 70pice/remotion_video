# 第一版口播与分镜

1. AI写完代码，就算完成任务了吗？还差得远。
画面：Snapcn TextBuild 分两行进入；代码生成完成的卡片，随后显示待验收标签。

2. 比如给网站加个登录页。写代码只是一步，还要明确需求、拆分任务、运行测试，最后由人验收。
画面：竖向流程：明确需求 → 拆任务 → 写代码 → 测试与验收，官方 Arrow 连接。
时间：5.57s ～ 15.10s

3. 这篇文章关注需求的全流程：把任务和依赖连起来，让不同的AI角色接力工作。
画面：三张角色卡逐步形成依赖图，中央结果卡标注可验证的产物。
时间：15.10s ～ 22.70s

4. 一个负责拆需求，一个负责实现，一个负责审查。交接的是任务状态和产物，不只是聊天。
画面：角色卡与 source-team 原文截图对应；明确人负责最终验收。
时间：22.70s ～ 31.30s

5. 看这个多Agent看板：待办、进行中、审查，再到完成。遇到阻塞，仍然需要人来判断。
画面：原文带标注的 Multica 看板全图后轻微放大，底部独立放大状态标签和阻塞提醒。
时间：31.30s ～ 40.13s

6. 云端开发，则让任务在远程环境继续跑。人可以从手机发起或查看进度，但上云不代表所有任务都能自动完成。
画面：手机任务卡 → 远程运行环境 → 结果回传的示意流程；清楚标注概念示意。
时间：40.13s ～ 50.63s

7. 但是，能跑不等于做得好。记录过程，整理失败案例，用评测验证修改后是否更好。原文的评测方案，还处于早期验证。
画面：过程记录、评测集、工作流优化和再次验证的闭环；MVP 标签，避免虚构已获得提效数据。
时间：50.63s ～ 62.43s

8. 所以，值得关注的不只是AI写了多少代码，而是它有没有把需求推进到可验证的结果。
画面：Snapcn 动态结论文字，需求卡转成带验收标记的结果卡，展示来源名称和AI配音标识。
时间：62.43s ～ 70.67s
