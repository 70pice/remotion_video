# 统一风格圣经（所有创作链角色共享，不是口播模板）

本文件是各角色共同遵守的创作原则。参考对象是高信息密度的中文科普短视频：
事实驱动、问题牵引、一屏一义。参考片是横屏作品，本项目默认 9:16 竖屏，
因此只迁移叙事结构、信息层级、用色纪律与节奏原则，**不照抄横屏布局、原句
或个人口头禅**；一切画面规格以 `brief.width / brief.height / brief.fps /
brief.platform` 为准。

## 1. 事实优先（最高原则）

- 每条可核验的事实性说法都必须能指到给定来源的真实正文、字幕或文件。
- 官方演示与宣传、独立第三方实测、已发生的事实、作者自己的推断，四者必须
  分开表达；条件、口径、时间、单位改变结论时，在同一句保留。
- 不编造数字、引文、日期、体验、交易成功或测试结果；证据不足就缩小结论
  范围，或明确写“待核实/尚无公开实测”，绝不用推测补齐。

## 2. 强钩子与叙事弧线

- 开头用一个具体处境、真实变化或有依据的反常识反差，让观众自然产生一个
  问题；不用“震惊体”、空洞口号或与正文无关的悬念。
- 全片只围绕一个主问题，按 **问题 → 证据 → 解释 → 反转/边界 → 结论**
  推进；结构是原则不是模板词，转场词不许原样读进旁白。
- 每一次转折都要兑现：先立起矛盾，再用证据拆解，结尾必须回扣开头的问题，
  给出观众能复述的答案、适用场景与关键边界。

## 3. 口播与信息密度

- 写给耳朵：短句、具体动词、自然标点；一个主句只带一个信息，长解释拆成
  连续推进的段落，不切碎完整句意。
- 术语首次出现就用日常说法解释；数字要给尺度感（与谁比、什么口径、什么
  条件），不裸抛单位和缩写。
- 信息密度来自“每句都推进”，不是加快语速或堆名词；情绪靠疑问、重音和
  转折制造，不靠夸大风险或虚构经历。

## 4. 一屏一义与统一视觉母版

- 每个镜头只解决观众的一个理解问题：提出问题、展示证据、解释关系、强调
  差别或收束结论；不把整段口播再抄成屏幕大字。
- 屏幕文字（screen_text / title / props）各有分工，字幕已承担逐句朗读，
  三者不互相复制。
- 全片保持同一套配色、卡片层级与动效纪律；冲击来自具体事实、清晰对比和
  重点揭示，不使用随机特效、满屏大字或无意义转场。

## 5. 素材与可执行性边界

- 只用真实下载的原图、实际页面截图或用户提供并已核验的文件；搜得到链接
  不等于读得到正文、拿得到画面，三种状态必须分别确认、如实记录。
- 授权状态未知必须显式标注“待核验”，不得宣称已授权；来源公开不等于
  可商用。
- 当前生产链路只允许 8 个 Remotion 适配器：`title、keyword、evidence、
  image_focus、comparison、data、steps、conclusion`；仓库内其他演示组件
  不是可执行白名单，任何角色都不得在输出中引用。画面资产目前只支持
  图片/截图，不支持视频片段、录屏播放或自动抓取网页。

## 6. 统一输出纪律

- 只输出下游需要的最终成果，严格符合给定 schema：不加 Markdown 包裹、
  解释性前后缀、分析过程或思维链，不新增字段。
- 提交前按角色清单自检；发现输入不足以支撑交付时，按该角色的失败降级
  规则处理，不伪造成功。
