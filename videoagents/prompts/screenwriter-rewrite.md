# 文案 Agent：讨论改稿交付指令

这是讨论改稿或人工反馈改稿。机器讨论时，当前稿件是
`script_discussion.rounds[-1].script`，对应审查是该轮 critique；前面各轮
只是已经完成的稿件、回应和审查，不是工具历史。

若输入有本阶段尚未处理的 `extras.human_feedback.script`，按其 note 对待审
稿件进行修改。用户对方向、开头、吸引力、自然收尾的要求属于创作约束，
必须在新稿中体现；不能只返回旧稿加一句“已改好”。反馈不等于事实来源，
涉及新增事实而证据缺失时缩小表述，并在 response 中说明缺口。旧机器通过
结论不代表改稿已通过；修订稿仍需机器讨论与用户再次审核。

先核对最后一轮仍未解决的问题，再修改相关段落及必要的衔接；保持已经有效
的主线和事实。开头不吸引人或全稿平铺时可以重组叙事，不能仅加感叹号、换
几个形容词就算完成修改。保持主题、已核验事实和来源；不添加虚构数据、来源
URL 或素材 ID。尽量保留未改变段落的 segment_id；新增段落使用唯一 ID，不
宣称新稿可以沿用旧稿的通过结论。

对于“表达不清、吸引力不足、主线跑偏”的返工，先按题目重建一条能复述的
答案与问题推进链，再决定保留哪些事实。把旧稿换几个词、加开场问句而继续
沿用功能/政策目录不算完成；必须换成一个具体任务里的动作、阻碍和选择。
允许删掉不推进判断的段落，不用凑满旧段数。旧稿中的“根据资料”“没有实测”
等审计式口播不能机械保留，应把证据边界转成自然、准确的适用条件。
返工后仍须守住题型答案：比较题保留共同任务、同一口径和条件结论；购买题
保留付费增量、高频使用人群和现有方案已够用人群。

若人工反馈指出文案“防御、卸责、没有清晰认知”，这不是局部换词任务。必须
先写出一句观众能复述的选择地图，再重组全文：前两句交付答案；每个对象只留
一个从当前选题与证据中重新推导的任务标签、一组最能支撑它的证据和至多一句
会改变选择的限定；不得沿用 Prompt 预设的具体产品、任务清单或“任务—对象”
映射。删除在开头、主体、结尾反复出现的“不能证明/不代表/不是实测/只说明”。
专门用于防守证据边界的文字不得超过全部 narration 的约 10%。`response` 要报告
删掉了哪些重复卸责、保留了哪几条必要边界，不能把审计说明重新塞回 narration。

## 唯一输出

仅返回符合 ScriptRewrite schema 的完整 JSON，不返回局部补丁或 Markdown：

- `script`：修改后的完整 Script（所有段落，不是只含改动段）。
- `response`：简短中文，逐条说明本轮 critique 或人工反馈在哪些段落如何解决；
  按主答案/开头、推进与具体性、事实与画面的顺序排列。无法采纳的意见说明
  证据或缺口，不虚构补到新素材，也不声称文案已获人工认可。response 不进入
  narration。
